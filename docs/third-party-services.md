# 第三方接入服务：五类怎么分辨

国内围绕 Claude Code 的第三方工具不是一类东西，混在一起比较没有意义。
按**你的 Key 和代码经过谁**来分，一共五类，风险和验证方法完全不同。

如果你已经选好了服务、只是配不通，直接看 [configuration.md](configuration.md)
和 [troubleshooting.md](troubleshooting.md)。

## 五类对照

| 类别 | 你的 Key 和代码经过谁 | 典型形态 | 付款前能自己验的事 |
|---|---|---|---|
| ① 网页端聚合站 / 镜像站 | **对方服务器（含对话内容）** | 网页聊天界面，不落地到本地 CLI | 几乎没有 |
| ② 开发者本地接入的中转服务 | 对方 API 网关（代码经过） | 改 `ANTHROPIC_BASE_URL` 后本地 CLI 直连 | 模型清单、经营主体、退款条款 |
| ③ 开源代理 / 配置管理 | **只经过你自己的机器** | 本地跑的脚本或客户端 | 全部源码 |
| ④ 云厂商托管集成 | 该云厂商 | 云控制台里的托管服务 | 主体、账单、SLA |
| ⑤ 国产模型替代 | 该模型厂商 | 换掉 Claude 用别的模型 | 主体、定价、模型能力 |

**为什么这么分**：Claude Code 是个本地 CLI，它把你的代码目录读进上下文再发出去。
所以真正要问的不是「哪家便宜」，而是**这条链路上多了谁**。

## ① 网页端聚合站 / 镜像站

给你一个网页聊天框，通常打包多个模型，按月或按次计费。

**它和 Claude Code 这个 CLI 没有关系**——你无法用它跑 `claude` 命令、无法让它读你的
本地代码目录。如果你的诉求是「在终端里用 Claude Code 写代码」，这一类直接排除。

**分辨方法**：看它有没有给你 `ANTHROPIC_BASE_URL` 这种能填进本地配置的东西。
没有，就是这一类。

## ② 开发者本地接入的中转服务

给你一个 API 端点和一个 Key，你在本地设两个环境变量，然后照常用官方的 `claude` 命令。
代码不离开你的机器去别的界面，但 **API 请求经过对方网关**。

配置方法见 [configuration.md](configuration.md)。这一类**付款前能自己验**的有三项：

**（a）模型清单免不免 Key 查**

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://你要查的服务地址/v1/models
```

返回 `200` 且能看到具体模型 ID 的，「支持哪些模型」这句话你当场就能验真伪。

⚠️ 返回 `401` **不是缺点**——把模型清单放在鉴权后面是常见设计，大厂几乎都这样。
它只说明这一项你没法在付款前自己核对，只能信官网文案。

**（b）经营主体查不查得到**

看官网页脚有没有公司名、ICP 备案号或境外主体注册号。查不到不必立刻判它不行，
但**把试用金额压到最低**，并在付款前把退款条款问清楚、留下书面记录。

**（c）端点是不是真的通**

```bash
curl -s https://你要查的服务地址/v1/messages \
  -H "content-type: application/json" \
  -H "anthropic-version: 2023-06-01" \
  -H "x-api-key: $ANTHROPIC_AUTH_TOKEN" \
  -d '{"model":"claude-sonnet-5","max_tokens":16,"messages":[{"role":"user","content":"hi"}]}'
```

返回里带 `"type":"message"` 就是通了。各类报错的含义见
[troubleshooting.md](troubleshooting.md)。

## ③ 开源代理 / 配置管理

一个开源项目，跑在你自己机器上。它**不提供模型能力**，只帮你管多套配置、
在不同端点之间切换。

把它当成「接入方案」是搞错了层次——你仍然需要一个可用的端点。
但如果你已经有 Key，这一类是纯赚：源码可读，链路上不多任何一方。

## ④ 云厂商托管集成

云厂商在自家控制台里提供的 AI 编程能力。主体、发票、合同、SLA 全是现成的，
**企业采购走这条路阻力最小**。代价是模型覆盖以该云的生态为界，跨厂商切换基本不可能。

## ⑤ 国产模型替代

不再用 Claude，改用国产模型驱动同一个 CLI。合规和支付问题一次性消失；
但 Claude Code 的一些行为是针对 Claude 模型调优的，换模型后表现会有差异，
需要你自己实测能否接受。

## 条件结论

- **要在终端里用 Claude Code 读本地代码** → ① 类直接排除，它给不了你 `ANTHROPIC_BASE_URL`
- **企业采购、要发票和合同** → ④ 类云厂商，或主体和备案可查的服务商。
  这时候「主体可查」比「模型多」重要得多
- **要在多家模型之间频繁切换比价** → 优先模型清单免 Key 可查的。
  省下的不是钱，是每次换模型都要开账号验一遍的时间
- **已经有可用的 Key，只是配置乱** → 你需要的是 ③ 类配置工具，不是再买一个接入服务

## 这份清单不能替你判断什么

- **不能判断稳定性、延迟、并发。** 这些只有真跑业务才知道，任何人在你付款前给出的
  这三个数字你都验不了——包括本文。
- **不能判断价格划算。** 各家计费口径不同（按 token / 按次 / 包月），
  脱离你的实际用量比价没有意义。
- **不能替代小额试用。** 先充最小额度跑通你自己的真实工作流，再决定要不要加钱。
- **① 类这里没有点名任何站点**，是刻意的：那一类更迭很快，点名等于给一个
  可能下个月就换域名的站背书。
